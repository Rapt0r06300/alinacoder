# AlinaCoder v0.2 — Real Zero-Cost Provider Fabric Hotfix Design

## Problem
The published v0.2 contains a zero-cost provider catalog/router contract, but the desktop conversation path does not execute inference through it. `DesktopWorkbench.send_message()` persists the user message and returns a receipt without invoking a provider. This makes provider failover and quota handling architectural-only rather than product-real.

This hotfix restores the already-approved v0.2 provider-atlas contract rather than replacing it with a smaller static provider list.

## Required product behavior
1. Every assistant response in `free-cloud` or `hybrid` mode must traverse the real provider fabric.
2. A route is admissible only when its cost proof is fresh and exactly zero-cost, with hard overage disabled/impossible for the exact account/route.
3. The runtime candidate atlas is the existing normative v0.2 atlas: Kilo Gateway, Z.AI, SambaNova Cloud, Groq, Cloudflare Workers AI, OpenRouter, Google Gemini API, Mistral, Hugging Face Inference Providers, Tencent TokenHub/Hunyuan, Alibaba Model Studio, SiliconFlow, Scaleway, Ollama local, Ollama Cloud, NVIDIA NIM, Cerebras, and OpenCode Zen. GitHub Models remains RETIRED/TOMBSTONED and must never be enrolled unless new authoritative GitHub evidence explicitly restores the service.
4. This atlas is discovery scope, not a permanent allowlist of free calls. Each exact provider/account/model route must re-prove its zero-cost and billing-mode state before dispatch. A provider whose current state is paid, trial-only, payment-gated, stale, unknown, or capable of paid overflow is skipped/quarantined.
5. Kilo/OpenRouter/Hugging Face and other aggregators must expose or constrain backend/fallback closure sufficiently to prove every provider-managed fallback remains zero-cost. Otherwise provider-side fallback is disabled and AlinaCoder performs explicit failover itself.
6. Direct first-party routes are preferred when equivalent because provider/model identity and billing state are easier to prove.
7. HTTP 429/quota exhaustion, provider unavailability, unhealthy routes, expired cost proof, model removal, pricing drift, or account-mode drift immediately makes that route ineligible for the current request and triggers another eligible zero-cost route.
8. Exhaustion forecasting should switch at a safe boundary before hard exhaustion when trustworthy remaining/reset telemetry is available.
9. Routing prefers the strongest verified-quality route that covers the task capability requirement while preserving same-lineage continuity when practical.
10. If all configured cloud routes are unavailable, `hybrid` falls back to the hardware-fit Ollama model already provisioned by LOT 19. `free-cloud` fails closed with `NO_ZERO_COST_ROUTE` rather than spending money.
11. Conversation continuity is provider-independent: the canonical transcript is serialized into the next provider request, and a provider switch never discards prior user/assistant turns.
12. The UI must show the active provider/model and expose provider enrollment/configuration without requiring a terminal.
13. Missing provider credentials never block the task when another eligible route exists; the candidate is marked `AUTH_REQUIRED` and routing continues.
14. Credentials are stored only behind secret handles/OS-backed protection; raw provider secrets never enter transcript, Git, logs, crash reports, or public Supabase state.

## Provider architecture
Create focused provider runtime under `src/alinacoder/intelligence_mesh/providers.py` and `provider_atlas.py`.

Core interfaces:
- `ProviderResponse(text, provider_id, model_id, quota_remaining, metadata)`
- `ProviderError(code, provider_id, model_id, retryable)`
- `ProviderDefinition(provider_id, protocol, base_url, discovery_url, auth_env, account_proof_required, aggregator)`
- `ZeroCostProvider` protocol with `discover()` and `complete()`.
- `ProviderAtlas` returning the normative candidate definitions.

Protocol families:
- `openai_chat`: Kilo Gateway, Z.AI, SambaNova, Groq, Cloudflare Workers AI, OpenRouter, Mistral, Hugging Face router, Tencent/Hunyuan where current account endpoint is OpenAI-compatible, Alibaba Model Studio compatible mode, SiliconFlow, Scaleway, NVIDIA NIM, Cerebras, OpenCode Zen and any other atlas route whose current official endpoint proves OpenAI chat compatibility.
- `gemini`: Google Gemini `generateContent`.
- `ollama`: local Ollama API.
- provider-specific adapters may override discovery/account/quota parsing where generic OpenAI compatibility is insufficient.

The implementation must not hard-code “free forever”. Provider definitions describe how to probe; `CostProofReceipt`/billing proof decide whether a discovered exact route is admissible now.

## Live zero-cost qualification
Introduce a `ZeroCostQualification` boundary. An exact remote route is enabled only when it has a fresh proof containing at least:
- exact provider/model/account identity;
- prompt/completion/request price == 0 OR structural hard-stop free entitlement;
- no PAYG/postpay/auto-reload/paid-fallback path for this route;
- proof source and expiry;
- quota remaining/reset where available;
- privacy/use-scope admission.

Structural safe classes from the normative spec remain: `ZERO_PRICE_MODEL`, `HARD_STOP_FREE_QUOTA`, `NO_PAYMENT_METHOD_FREE_TIER`, `FREE_MODE_PAYG_DISABLED`. Unknown or conflicting state is fail-closed.

Provider examples must follow their normative safety rules: SambaNova requires Free Tier/no payment method; Cloudflare must distinguish Workers Free from Paid; Mistral requires PAYG off; Tencent requires post-payment off; Alibaba `Free Quota Only` must be proven; OpenRouter only exact zero-price/free closure; Ollama Cloud/OpenCode Zen/Hugging Face/NVIDIA/Cerebras/Scaleway and other trial/credit/payment-gated routes are admitted only when their exact current account behavior proves autonomous spend cannot occur.

## Runtime orchestration
Create `InferenceFabric` in `src/alinacoder/intelligence_mesh/fabric.py`.

Inputs:
- transcript messages
- capability requirement
- mode: `local-only | free-cloud | hybrid`
- configured/enrolled provider instances

Algorithm:
1. Refresh the live provider catalog from configured atlas providers.
2. Reject candidates lacking fresh exact zero-cost qualification.
3. Select an eligible route with `FrontierRouter`.
4. Execute the provider request with the unchanged canonical message sequence.
5. On success, normalize quota telemetry, update route health/quota, persist provenance and return response.
6. On 429/quota exhaustion/unavailability, quarantine/deplete that exact route and select again without retrying it in the same request.
7. Prefer safe pre-emptive handoff when exhaustion forecast predicts mid-stage failure.
8. In hybrid mode, fall back to Ollama after remote candidates are exhausted.
9. In free-cloud mode, return fail-closed when no zero-cost cloud route remains.

## Desktop integration
`DesktopWorkbench` owns an optional `InferenceFabric`. `send_message()` must:
1. persist the user message,
2. construct canonical transcript context,
3. call the fabric,
4. persist the assistant response plus provider/model/route provenance,
5. return a receipt containing route information and assistant text.

The GUI displays assistant output and active provider/model. First-run provider selection is preserved. Provider setup uses user-authorized credentials only; AlinaCoder never creates accounts, bypasses verification, links payment methods, or fabricates identities to multiply free quotas.

## Zero-cost safety
- `MAX_PAID_SPEND_EUR = 0.00` remains absolute.
- Paid routes are never admitted.
- Unknown/stale price or billing state is never treated as free.
- Provider-side fallback is disabled unless its entire closure is proven zero-cost.
- Local Ollama is the final hybrid fallback and is independent of cloud quota.
- “All free models” means all currently discoverable, configured, qualified routes in the normative atlas; the runtime dynamically adds/removes exact models as provider catalogs change.

## Tests and release gate
The v0.2 release cannot be republished until all of the following pass on the same SHA/artifact:
- atlas contains every normative provider above and tombstones GitHub Models;
- real desktop conversation calls the fabric and persists an assistant response;
- multiple models on one provider can be ranked/switched;
- quota=0 and HTTP 429 trigger provider/model failover;
- provider exhaustion can fail over across provider boundaries;
- paid/stale/unsafe-account route is rejected before request;
- transcript continuity survives provider and model switches;
- hybrid cloud exhaustion falls back to Ollama;
- free-cloud exhaustion fails closed without local fallback or spend;
- generic OpenAI-compatible, Gemini, and Ollama adapters parse representative official API responses and quota errors;
- per-provider definition/safety metadata exists for the complete atlas;
- packaged Windows E2E includes deterministic provider-fabric E2E using fake transports plus the real Ollama smoke already required by LOT 19;
- existing LOT 1–19 acceptance stays green;
- release manifest records `real_provider_fabric=true`, atlas version/provider IDs and zero-cost-only policy;
- v0.2.0 is rebuilt and republished from the new validated SHA; old binaries must not remain presented as the current v0.2.0 assets.
