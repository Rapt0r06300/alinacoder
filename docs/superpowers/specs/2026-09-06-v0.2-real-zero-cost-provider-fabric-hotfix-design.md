# AlinaCoder v0.2 — Real Zero-Cost Provider Fabric Hotfix Design

## Problem
The published v0.2 contains a zero-cost provider catalog/router contract, but the desktop conversation path does not execute inference through it. `DesktopWorkbench.send_message()` persists the user message and returns a receipt without invoking a provider. This makes provider failover and quota handling architectural-only rather than product-real.

## Required product behavior
1. Every assistant response in `free-cloud` or `hybrid` mode must traverse the real provider fabric.
2. A route is admissible only when its cost proof is fresh and exactly zero-cost, with hard overage disabled.
3. Initial supported cloud families are OpenRouter free routes, Google Gemini Free tier, and Groq Free Plan. They require the user's own provider credentials/configuration where the provider requires authentication.
4. OpenRouter discovery is dynamic from its model catalog and only admits models whose prompt/completion/request price is zero or models explicitly identified by the provider as free routes.
5. Gemini and Groq use provider-specific adapters and explicit free-tier enrollment. No paid-tier fallback is ever attempted.
6. HTTP 429/quota exhaustion, provider unavailability, unhealthy routes, expired cost proof, or model removal immediately makes that route ineligible for the current request and triggers another eligible zero-cost route.
7. Routing prefers the highest verified quality route that covers the task capability requirement, while preserving same-lineage continuity when practical.
8. If all configured cloud routes are unavailable, `hybrid` falls back to the hardware-fit Ollama model already provisioned by LOT 19. `free-cloud` fails closed with a clear `NO_ZERO_COST_ROUTE` result rather than spending money.
9. Conversation continuity is provider-independent: the canonical transcript is serialized into the next provider request, and a provider switch never discards prior user/assistant turns.
10. The UI must show the active provider/model and expose provider configuration without requiring a terminal.

## Provider interfaces
Create a focused provider runtime under `src/alinacoder/intelligence_mesh/providers.py`.

- `ProviderResponse(text, provider_id, model_id, quota_remaining, metadata)`
- `ProviderError(code, provider_id, model_id, retryable)`
- `ZeroCostProvider` protocol with `discover()` and `complete()`.
- `OpenRouterProvider`, `GeminiProvider`, `GroqProvider`, and `OllamaProvider`.

Credentials are loaded from explicit application configuration/environment-backed secret references, never committed to the repository. Provider adapters use only official HTTPS APIs.

## Runtime orchestration
Create `InferenceFabric` in `src/alinacoder/intelligence_mesh/fabric.py`.

Inputs:
- transcript messages
- capability requirement
- mode: `local-only | free-cloud | hybrid`
- configured provider instances

Algorithm:
1. Refresh the provider catalog.
2. Select an eligible route with `FrontierRouter`.
3. Execute the provider request.
4. On success, update quota/health and return response.
5. On 429/quota exhaustion/unavailability, quarantine/deplete the failed route and select again.
6. Never retry the same exhausted route in the same request.
7. In hybrid mode, fall back to Ollama after cloud candidates are exhausted.
8. In free-cloud mode, return fail-closed when no zero-cost cloud route remains.

## Desktop integration
`DesktopWorkbench` owns an optional `InferenceFabric`. `send_message()` must:
1. persist the user message,
2. construct transcript context,
3. call the fabric,
4. persist the assistant response plus provider/model provenance,
5. return a receipt containing route information.

The GUI displays assistant output and active provider/model. First-run provider selection is preserved, but actual credentials are configured through provider settings/application secret storage rather than embedded values.

## Zero-cost safety
- Paid routes are never admitted.
- A provider response cannot silently upgrade the account or accept overage.
- Unknown/stale cost state is treated as ineligible.
- Local Ollama is always zero monetary API cost and is the final hybrid fallback.
- “All free models” means all currently discoverable admissible routes from configured supported providers, not an unsafe static promise that every public model/service on the internet is supported forever.

## Tests and release gate
The v0.2 release cannot be republished until all of the following pass on the same SHA/artifact:
- real desktop conversation calls the fabric and persists an assistant response;
- quota=0 and HTTP 429 trigger provider/model failover;
- paid/stale route is rejected before request;
- transcript continuity survives provider switch;
- hybrid cloud exhaustion falls back to Ollama;
- free-cloud exhaustion fails closed without local fallback or spend;
- provider adapters correctly parse representative official API responses;
- packaged Windows E2E includes a deterministic provider-fabric E2E using fake HTTP transports plus real Ollama smoke already required by LOT 19;
- existing LOT 1–19 acceptance stays green;
- release manifest records provider-fabric capability and the release is rebuilt on the new SHA.
