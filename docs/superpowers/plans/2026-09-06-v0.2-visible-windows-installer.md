# Visible Windows Installer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the console-like default `AlinaCoderSetup.exe` experience with a persistent graphical Windows installer that visibly reports progress/errors, supports retry, creates normal Windows integration, and is required by the v0.2 release gate.

**Architecture:** Keep the existing LOT19 bootstrap/CLI engine as the source of truth. Add a UI-neutral setup event/logging/controller layer, then a Tkinter Windows GUI that consumes that controller. Default no-argument setup entry selects GUI mode; explicit CLI/`--quiet` remains headless. Packaging switches the setup executable to `--windowed`, and CI adds a packaged UI state-machine oracle plus same-SHA release evidence.

**Tech Stack:** Python 3.12/3.13 stdlib, Tkinter, ctypes/winreg/PowerShell-hidden shortcut creation, PyInstaller 6.16, GitHub Actions Windows runners.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.2-visible-windows-installer-design.md`

## Global Constraints
- Work directly on `main`; no final auxiliary branches.
- Default double-click must never open a black console.
- `--quiet` and existing lifecycle CLI flags must remain compatible.
- Existing SHA-256/WinVerifyTrust/ownership/fail-closed bootstrap behavior must not be weakened.
- No shortcut/uninstall registration before bootstrap readiness is proven.
- Errors must remain visible in GUI and durable in a persistent local log.
- Release remains blocked until LOT19, provider fabric, visible installer, provenance and final acceptance all pass on the same SHA/artifacts.
