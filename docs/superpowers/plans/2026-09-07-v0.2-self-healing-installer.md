# AlinaCoder v0.2 Self-Healing Installer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `AlinaCoderSetup.exe` autonomously repair recoverable installation failures and complete a fully verified AlinaCoder installation without damaging the last healthy state.

**Architecture:** Add a UI-neutral recovery policy/journal module, replace direct application copy with transactional promotion, wrap install/upgrade/repair in a bounded self-healing runner, then bind the visible setup controller to that runner. Existing prerequisite provenance, MinGit staging, Ollama resume, Windows filesystem retry, rollback and release gates remain authoritative.

**Tech Stack:** Python 3.11+, pathlib/shutil/os/hashlib/json, existing unittest suite, PyInstaller packaging, GitHub Actions Windows runners.

**Spec:** `docs/superpowers/specs/2026-09-07-v0.2-self-healing-installer-design.md`

## Global Constraints

- Supported platform remains Windows 10/11.
- Default installation remains per-user under `%LOCALAPPDATA%\\AlinaCoder`.
- Never bypass SHA-256, Authenticode, repository allow-list, version, Ollama health, model presence, or smoke-inference gates.
- Never purge user data or pre-existing third-party prerequisites during automatic recovery.
- Preserve the previous healthy `AlinaCoder.exe` whenever promotion or bootstrap fails.
- Default automatic attempt budget: 4 complete attempts with bounded exponential backoff.
- Cancellation and fatal provenance/security failures stop immediately.
