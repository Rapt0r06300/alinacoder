# AlinaCoder v0.2 Windows 10/11 Release Finalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish AlinaCoder v0.2.0 from `main` only after the exact packaged `AlinaCoder.exe` and `AlinaCoderSetup.exe` pass fail-closed CI, LOT19, provider/provenance/acceptance gates, and explicit Windows 10/11 compatibility contracts.

**Architecture:** Keep the product's setup executable windowed for real users, but always wait for it explicitly in CI/publish automation. Bind both Windows executables to an explicit Win32 compatibility manifest declaring the Microsoft Windows 10/11 `supportedOS` GUID, preserve `minimum_windows_major = 10`, and make publication consume only same-SHA CI artifacts and evidence.

**Tech Stack:** Python 3.12/3.13, PyInstaller 6.16.0, Tk/Win32, PowerShell/GitHub Actions, GitHub Releases, unittest.

**Spec:** `docs/superpowers/specs/2026-09-04-alinacoder-v0.2-codex-class-live-agent-workbench-amendment.md`

## Global Constraints

- Work directly on `main`; the user explicitly requires one branch only.
- Release version remains `v0.2.0`.
- Target Windows major version is 10, covering Windows 10 and Windows 11.
- Never publish from a stale SHA or from incomplete evidence.
- `AlinaCoderSetup.exe` remains a graphical/windowed executable by default.
- Every setup CLI/smoke invocation in automation must wait for the process and inspect its process `ExitCode`.
- Do not claim Windows 10/11 release readiness unless compatibility metadata and same-artifact packaged gates pass.
