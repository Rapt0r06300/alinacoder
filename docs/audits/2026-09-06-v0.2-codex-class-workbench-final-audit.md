## LOT19 timeout root cause and final correction

A previous packaged Windows run (`34055961969`) passed both cores, build, SBOM, attestations, provenance and packaged smoke, but the LOT19 step hit its 20-minute global timeout. The terminal cleanup showed persistent `ollama app` / `ollama` descendants still alive and no assertion failure before timeout.

Root cause: LOT19 used `Start-Process -Wait -PassThru` for the windowed `AlinaCoderSetup.exe`. During the clean bootstrap, setup installs/starts Ollama, which has persistent child processes. The PowerShell `-Wait` process-tree semantics therefore allowed those descendants to keep the CI wait alive after the setup process itself had completed.

The final boundary in `.github/workflows/ci.yml` now:

- centralizes all nine setup lifecycle launches through `Invoke-Lot19Setup`;
- starts `AlinaCoderSetup.exe` with `-PassThru` but not `-Wait`;
- calls `WaitForExit(timeout)` on the setup process object itself;
- preserves process-object exit-code checks;
- assigns bounded per-scenario budgets;
- emits process and receipt diagnostics on timeout;
- retains a 30-minute fail-closed global LOT19 bound.

The behavior is protected by `tests/test_lot19_setup_process_contract.py` and was developed RED → GREEN. The RED run was `34058905439`; the GREEN implementation commit was `d692e4b3d2764a5f32454437dfa004167157df15`.
